# Демо-наповнення каталогу

Генератор будує `seed.sql`, який доводить локальну базу до стану «як у справжньому магазині»:
50 категорій з коректними атрибутами, бренди, ~325 товарів з варіантами, демо-продавці й покупці,
відгуки з відповідями.

## Запуск

```powershell
# 1. (за потреби) перегенерувати SQL після зміни даних
node backend/scripts/seed/generate.mjs

# 2. застосувати до локальної бази (з кореня проєкту)
$pw = (Select-String -Path .env -Pattern '^POSTGRES_PASSWORD=(.*)').Matches.Groups[1].Value
Get-Content backend/scripts/seed/seed.sql -Raw |
  docker exec -i -e PGPASSWORD=$pw postgres-primary psql -h 127.0.0.1 -U postgres -d shagox -v ON_ERROR_STOP=1 -q
```

Після запуску скиньте кеш даних у Redis (контейнер `redis`, `FLUSHDB`) або перезапустіть API,
бо визначення атрибутів кешуються.

## Що робить seed.sql

Усе в одній транзакції: при помилці база не змінюється. Скрипт можна запускати повторно.

1. Синхронізує лічильники identity (після імпорту дампу вони відставали від даних).
2. Доповнює довідники (кольори, сокети, форм-фактори, 80 PLUS, тип матриці…) і бренди
   кожної категорії, з перекладами uk/en/de.
3. Приводить атрибути категорій до схеми з `data/catalog-*.mjs`:
   `brand` — атрибут товару, `color` — довідник, нерелевантні атрибути видаляються.
4. Створює демо-користувачів (email `@shagox.demo`, без пароля) і видаляє їхнє попереднє наповнення.
5. Товари з тими самими назвами, що вже є в базі, **оновлюються** (атрибути, опис, ціни в ₴,
   варіанти; фото зберігаються). Решта додається від імені демо-продавців.
6. Генерує відгуки та відповіді продавців.

## Дані

| Файл | Вміст |
|---|---|
| `data/dictionaries.mjs` | спільні довідники значень |
| `data/attributes.mjs` | каталог атрибутів: тип, довідник, назви uk/en/de |
| `data/catalog-*.mjs` | категорії: бренди, схема атрибутів, товари |
| `data/people.mjs` | демо-користувачі та тексти відгуків |

Генератор перевіряє дані (типи, значення довідників, обов'язкові атрибути, унікальність назв)
і зупиняється з поясненням, якщо щось не так.

## Обмеження

- **Фото нових товарів** беруться з наявних товарів тієї ж категорії (Cloudinary), тому вони
  можуть не відповідати моделі. `PublicId` має префікс `seed-shared/`, щоб видалення демо-товару
  не видалило оригінальне фото. Для презентації варто завантажити справжні фото через сайт.
- Демо-користувачі не мають пароля, увійти під ними не можна.
