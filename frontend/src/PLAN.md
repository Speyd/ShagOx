# ShagOx (Marketly) — стан проєкту

Оновлено: 15.11.2026

## Коротко

«База» для маркетплейсу є: можна зареєструватися, виставити товар, знайти його в каталозі,
відкрити сторінку, додати в кошик чи обране, порівняти, залишити відгук і керувати своїми
товарами в профілі. Є адмінка для всіх довідників і сутностей.

Єдина велика дірка в основному сценарії — **замовлення**: бекенду немає, тому покупка
закінчується на сторінці вибору оплати. Решта прогалин — це другорядні сторінки-заглушки.

Збірка: `npm run build` проходить, `npm run lint` — 0 помилок, бекенд збирається.

## Що є лише частково / заглушки

| Що | Стан | Що треба |
|---|---|---|
| **Оформлення замовлення** | Кошик → дані доставки → вибір оплати працюють, але кнопка «Продовжити» лише показує тост | Бекенд `Orders` + створення замовлення + сторінка «Дякуємо» |
| Профіль → Замовлення | Вкладки є, список завжди порожній | Залежить від `Orders` |
| Відстеження замовлення | Статична сторінка | Залежить від `Orders` |
| Профіль → Інформаційна панель | Лише заголовок «Моя статистика» | Мінімум: к-сть товарів, переглядів, відгуків, середня оцінка |
| Сповіщення | Усі вкладки показують «Немає нових сповіщень» | Можна прибрати з меню або лишити як «у розробці» |
| Вибір категорій (онбординг) | Зберігається в браузері, але ніде не використовується | Або використати на головній, або прибрати |
| Головна | Hero, промо-блоки, «новинки» — статичні; реальні тільки категорії | Можна показати реальні популярні / нові товари |

## Виправлено в цій сесії

- **Додавання товару не працювало взагалі.** Варіанти створювались у транзакції, а оголошення
  перевірялось через репліку БД, яка ще не бачила незакомічений запис → «Оголошення не знайдено».
- **Стан товару англійською.** У таблицях перекладів (стани, статуси, міста, регіони) статус був
  записаний як `'0'` замість `'Active'` → API не знаходило переклад. Виправлено в БД і в сід-скрипті;
  фронт тепер завжди просить українську.
- **Редагування товару губило зміни.** Ціна не зберігалась (регістр полів), фото ігнорувались
  (`images` замість `Pictures`), атрибути товару затирались, синхронізація фото падала.
- **Фото у відгуку не можна було прибрати.** Форма редагування не показувала фото, бекенд приймав
  JSON (файли не передати) і пропускав синхронізацію фото, якщо текст не змінився.
- **Безпека:** можна було змінити ціну чужого варіанта через своє оголошення.
- Новий товар не зʼявлявся в «Моїх товарах» до години (кеш); список тепер від нових до старих.
- `GET /advertisements/short-search` падав з 500.
- `npm run build` не збирався (8 помилок TypeScript); видалено 3 мертві дублікати адмін-сторінок.
- Биті посилання: «Додати оголошення» з порожньої категорії, текст «немає обраних товарів» у замовленнях.

## Відомі проблеми / технічний борг

- **Читання з репліки під час запису.** Частина сервісів читає сутність з репліки, а потім змінює
  її в основній БД. Для товарів, фото і відгуків виправлено; інші місця з тим самим шаблоном
  (кошик, профіль, адмін-оновлення) варто перевірити, якщо щось «не зберігається».
- `Repository.Update` ковтає винятки й повертає `false` — помилки збереження можуть бути непомітні.
- Кеш Redis живе 1 год: після ручних змін у БД дані на сайті оновлюються не одразу.
- У БД місто Київ має `Id = 0`.
- Опис типів товарів у БД — російською (на сайті не показується).
- Тестів немає ні на фронті, ні на бекенді.
- Залежності з відомими вразливостями: `Newtonsoft.Json 9.0.1`, `Microsoft.AspNetCore.WebUtilities 2.3.9`.
- Бандл фронта > 500 КБ (немає code-splitting для основних сторінок).
- `README.md` описує проєкт дуже загально.

## План до захисту (за пріоритетом)

1. **Замовлення (обовʼязково для «бази»).** Мінімум: сутність `Order` + `OrderItem`, створення з
   обраних позицій кошика (адреса, спосіб оплати), зменшення `Stock`, очищення кошика,
   список замовлень у профілі зі статусом. Оплату можна імітувати.
2. **Прогнати ручний чекліст нижче** на чистому акаунті й виправити те, що впаде.
3. Інформаційна панель профілю — прості цифри з наявних даних.
4. Сповіщення / онбординг категорій — або прибрати з навігації, або позначити «скоро».
5. Оновити `README.md`: як запустити (docker, міграції, сід), архітектура, скріншоти.
